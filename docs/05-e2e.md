# Prompt 05 — End-to-end reliability

This step wires the dashboard, FastAPI orchestrator, kubectl evidence, OpenRouter diagnosis, and Supabase history into one product flow.

## Flow

1. Sign in with Supabase Auth.
2. The dashboard loads **every context** from your local kubeconfig via `GET /clusters`.
3. Click a cluster. The UI starts an investigation row and calls `POST /investigate` with that context.
4. FastAPI collects pods, logs, events, deployments, and networking, then runs AI (or local correlation).
5. Progress steps stream through Supabase Realtime.
6. The diagnosis appears. History is saved on the same row.

Auth, history, and realtime stay on **Supabase**. There is no InsForge dependency.

## Errors (UI-friendly)

The API never returns stack traces. Typical messages:

- Missing kubeconfig
- Cluster unreachable / kubectl timeout / permission denied
- OpenRouter unavailable (local correlation is used instead)
- Request timeout / backend unreachable
- Auth session missing

## Healthy cluster

If nothing is wrong:
